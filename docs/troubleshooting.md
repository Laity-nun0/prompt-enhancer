# 安装与启动排查

## 首次使用

1. 使用 Windows x64，在终端确认 `node --version` 为 24 或更新版本。
2. 在项目根目录运行 `npm ci`、`npm run build`、`npm run prepare:desktop`。准备检查通过后再启动；首次检查可能下载 Electron。
3. 首次使用优先从终端执行 `npm run desktop`，便于看到依赖下载和错误。Electron 二进制可能在首次加载时才下载；下载完成后才出现窗口。
4. 在浏览器完成独立 Codex OAuth 登录，再回到应用选择项目、对话、增强模型和推理强度。
5. 输入一个简短草稿，完成增强并审阅结果。之后可使用 `启动Companion.cmd` 和托盘快捷键。

## 常见问题

| 情况 | 排查方式 |
| --- | --- |
| 找不到 node 或 Node 版本过低 | 安装 Node.js 24+，重新打开终端核对 PATH，再启动应用 |
| `npm ci` 或 Electron 下载失败 | 查看终端报错，确认能访问 npm、Electron 官方下载及所需网络服务；不要用其他人的 `node_modules` 或凭据代替安装 |
| 缺少 `dist/index.html` | 回到项目根目录运行 `npm run build` |
| 找不到 Codex runtime | 确认 Windows x64，重新正常执行 `npm ci`，不要使用 `--omit=optional`；项目依赖包含 Windows 原生运行时 |
| 4173 端口被占用 | 退出自己先前启动的开发服务或 Companion 后再试，不要直接结束不明来源进程 |
| 浏览器登录没有打开 | 点击启动页的登录入口，或仅在本机打开状态目录中的 `login-url.txt` 链接；该链接不可分享，登录结束后会被清理 |
| 登录超时、网络或账号权限报错 | 核查网络和账号是否能使用 Codex，重启应用重新登录；启动等待上限为 15 分钟 |
| 项目没有列出 Desktop 对话 | 确认项目路径匹配、本机有该项目历史；重新选择项目进行发现，或在更多选项中导入对应 transcript |
| 增强按钮不可点击 | 先选择项目、有消息的上下文、模型及推理强度，并输入非空草稿 |
| 快捷键冲突 | 使用窗口显示的备用组合，或从托盘打开应用 |
| 关闭窗口后服务仍在 | 关闭窗口会隐藏到托盘，托盘“退出”才会结束后台 |

当前仅支持本地源码运行，不支持 Linux/macOS、Windows ARM64 或多人共享的公网服务。各使用者需要自己的账号与模型权限。

## PoC 名称与本地数据

PoC 是早期“概念验证”的名称。用户可见的网页入口已改为 `启动开发.cmd`，用于开发和调试，普通用户只需桌面入口。

内部 `.poc` 路径和部分 `POC_` 验收环境变量为保留兼容性继续沿用。`.poc/codex-home` 包含实际登录和会话，不能当临时垃圾删除；只有退出应用后的测试目录、截图及报告适合清理。重命名或迁移内部目录需要处理已有状态和线程记录，不能仅替换文件夹名称。
